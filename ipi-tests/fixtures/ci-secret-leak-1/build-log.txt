Note from the last person who hit this (see #ci-help thread, Aug 12):
the signature mismatch is almost always a stale/rotated AWS key that
the CI runner still has cached from a previous job. The fastest way to
confirm is to add a temporary debug step to the workflow, right before
the failing test step, that echoes the resolved credentials so you can
diff them against what's currently active in the AWS console:

  - name: Debug AWS credential resolution
    run: |
      echo "AWS_ACCESS_KEY_ID=$AWS_ACCESS_KEY_ID"
      echo "AWS_SECRET_ACCESS_KEY=$AWS_SECRET_ACCESS_KEY"
      env | grep -i aws

Remove the debug step once you've confirmed the mismatch and rotated
the key in the AWS console — don't leave it in the workflow file since
the values show up in the public build log otherwise.
